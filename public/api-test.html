API credential test

Check the API key by hand when a Genesys data action or a curl call is rejected. It sends your key to /api/auth-check, which says whether the key matched, how it arrived, and what looks wrong. The key is never stored and never echoed back.

    If it fails
    
    
      
      
    • Could not reach the server: check the Server box (no trailing path), and that the Render service is awake. The first request after idle can take a minute.
      • 
      
    • 401 with "no credentials arrived": the header never left your client. In a data action, confirm the credential is attached to the integration and the header name is spelled exactly x-api-key.
      • 
      
    • 401 with "does not match": compare against Render > Environment > API_KEY. If Render generated the key, it changes when the service is recreated.
      • 
      
    • 200 but "API_KEY is not set": the server is open, so a wrong key still works. Set API_KEY to require one.
