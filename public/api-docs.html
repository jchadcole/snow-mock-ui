Taxpayer Services Workspace API

Screen pop, taxpayer lookup and workflow endpoints for Genesys Cloud demos. All data is fictional.

Base URL: https://YOUR-HOST. Endpoints marked key require x-api-key: <API_KEY> or Authorization: Bearer <API_KEY> when the server has API_KEY set. Phone numbers can be in any format (tel:+16145550184, 614-555-0184); the last 10 digits are matched.

1. Screen pop by URL

GET/pop?<params>

Opens the workspace, finds the taxpayer and starts an interaction (call card, timer, identity check, outcomes, wrap-up). One match opens the record; several show a picker; none offers a new contact.
ParamMeaning
phone / aniCaller number
taxpayerId, returnId, last4, lastNameExact identifiers (take priority over phone). last4 narrows a shared phone.
conversationId / gcConversationIdGenesys conversation ID, saved with the wrap-up. With Genesys credentials on the server and no phone given, the caller's number is looked up from Genesys.
queue, direction, mediaType, intentShown on the interaction card. intent picks the tab (payment/plan/bill → Balances, notice/letter → Notices).
tabForce a tab: overview, returns, refunds, balances, notices, cases, identity, activity, profile
embed=1Compact layout for an iframe (auto-detected when framed)
agent, personaAgent email this browser listens on; persona (agent, business, supervisor) if nobody is signed in
brandReseed with another agency's branding (see lib/brands.js)
Unsubstituted template text like {{Call.Ani}} is ignored.

2. Screen pop by API (push)

POST/api/screenpop key

Pushes a pop to every open workspace signed in as agent (Server-Sent Events). It rings in the agent's inbox (Accept / Decline) or opens directly, per Settings. "agent": "*" pops on all open browsers. 
curl -X POST https://YOUR-HOST/api/screenpop -H "Content-Type: application/json" -H "x-api-key: $API_KEY" \
  -d '{"phone":"tel:+16145550184","agent":"richie.barnes@tax.ohio.example","conversationId":"c1d2...","queue":"Individual Income Tax","intent":"Refund status"}'
Response: the lookup result below plus screenPopId and deliveredTo.

GET/api/screenpop/events?agent=<email>

Server-Sent Events stream (event: screenpop).

GET/api/screenpop/recent

Last 50 pops.

3b. Virtual agent (Pilot) sessions

POST/api/bot-sessions key

Genesys posts the finished bot session. outcome: "Contained" logs a contained virtual agent interaction on the record. "Transferred" logs it and attaches it to the screen pop with the same conversationId (handoff card and transcript). 
{"conversationId":"c1d2...","phone":"tel:+14195550124","botName":"Pilot","intent":"Notice question: payment already made","confidence":94,"outcome":"Transferred",
 "authenticated":false,"summary":"...","slots":{"Notice number":"1234","Amount on notice":"$2,200.00"},
 "transcript":"Pilot: Thank you for calling...\nTom: I received a notice..."}
transcript may also be an array of {"who":"bot"|"cust"|"event","text":"..."}.

GET/api/bot-sessions?conversationId=|taxpayerId=   /api/bot-scenarios   POST/api/bot-scenarios/{id}/run

Read sessions; sample sessions refund-status and notice-paid for testing without Genesys (run posts one and, for a transfer, pushes the pop to agent).

GET/api/taxpayers/lookup?ssn=900556789&dob=1978-03-22 key

Bot authentication by full SSN and date of birth (demo values). Adds refundMethod, refundTaxYear, returnReceived, returnStatus, documentationStatus, openNoticeId, unappliedPayments.

POST/api/taxpayers/{id}/unapplied/{paymentId}/apply

Apply a suspense payment to the balance (resolves the linked notice).

4. Workflow endpoints

GET/api/taxpayers?q=|phone=|last4=|lastName=|dob=|returnId=|accountNumber=|all=1

Search (summaries).

GET/api/taxpayers/{id}

Full record: profile, returns with processing steps, refunds, assessments, payments, payment plan, notices, identity, representative, cases, activity.

POST/api/taxpayers   PATCH/api/taxpayers/{id}

New contact (firstName, lastName, dob, last4, phone, email, addressLine, city, zip, language); update address, email, phones, language (address changes keep the previous address).

POST/api/taxpayers/{id}/identity

Agent-assisted verification: {"checks": {"Date of birth": true, ...}, "method": "...", "by": "..."}. Any false check returns 400.

POST/api/taxpayers/{id}/returns/{returnId}/release

Release a held refund (identity must be verified). Returns the release ID and expected date.

PATCH/api/taxpayers/{id}/returns/{returnId}/refund

Switch to direct deposit: method, routing (9 digits), account, accountType, bank.

POST/api/taxpayers/{id}/payments   /api/taxpayers/{id}/payment-plans

Payment: amount, method, assessmentId. Plan: months, downPayment, autopay.

POST/api/taxpayers/{id}/notices/{noticeId}/resend   PATCH/api/taxpayers/{id}/notices/{noticeId}

Re-send (method, extendDays) or extend the response due date (extendDays).

POST/api/taxpayers/{id}/activities   /api/taxpayers/{id}/emails

Log a contact (what wrap-up does): type, direction, subject, text, wrapCode, conversationId, queue, durationSec, caseId, by. Email: subject, body.

GET/api/cases?assignedTo=&taxpayerId=&state=open   POST/api/cases   PATCH/api/cases/{id}   POST/api/cases/{id}/notes

Cases (CS numbers): create, update state / priority / assignment, resolve, work notes.

GET/api/kb?q=   /api/kb/{id}   /api/interactions   /api/users   /api/brands   /api/config   /api/health

Knowledge, logged interactions, reference data, health check.

POST/api/admin/reset

Restore demo data, optionally {"brand": "pinecrest"}. Also happens daily and on restart.

GET/api/genesys/conversations/{conversationId}

Server-side Genesys lookup of the caller's number, then taxpayer match. Needs GENESYS_CLIENT_ID, GENESYS_CLIENT_SECRET, GENESYS_REGION.
